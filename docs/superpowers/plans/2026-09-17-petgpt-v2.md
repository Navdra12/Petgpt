# PetGPT v2 Implementation Plan

> **For agentic workers:** Use `superpowers:executing-plans` to implement this plan task by task after implementation is authorized. Use `superpowers:subagent-driven-development` only when delegation is authorized. Checkboxes track actual completed work. This document is a plan, not an implementation or a claim that tests have run.

**Goal:** Evolve the working Windows PetGPT MVP into a character-pack companion with explicit hard-RP activation, bounded character-specific reactions, tray controls, and native PetChats navigation.

**Architecture:** Preserve the root WPF application and native ChatGPT WebView. Introduce focused components inside the application, data-only packs, a pure animation reducer, and an attribute-only reaction bridge. Keep the original persistent browser profile and provide feature-specific fallbacks.

**Tech stack:** C#, WPF, .NET 8 baseline, existing `Microsoft.Web.WebView2` `1.0.4191.47`, `System.Text.Json`, Windows Forms `NotifyIcon`; xUnit for deterministic C# tests and development-only Playwright for synthetic DOM tests. A separate .NET 10 LTS compatibility change is required before release beyond .NET 8's support period.

**Spec:** [PetGPT v2 design](../specs/2026-09-17-petgpt-v2-design.md). When integrating these documents into the repository, place the design at `docs/superpowers/specs/2026-09-17-petgpt-v2-design.md` and this plan at `docs/superpowers/plans/2026-09-17-petgpt-v2.md`, updating their mutual links. Do not create an application rewrite to match a proposed folder tree.

**Baseline:** `Navdra12/Petgpt`, `main`, `c0c478877257118be849d751e2a8ee60c78e6ba4`. Re-read the current branch before changing it. The assessment read 20 text files; it did not compile or run the Windows app and did not probe an authenticated ChatGPT page.

## Global constraints

- The real `https://chatgpt.com/` website remains the chat UI. No OpenAI API, conversation engine, copied history, network-body interception, or conversation text extraction.
- Preserve `%LOCALAPPDATA%\PetGPT\WebView2` exactly. Never read, export, or store credentials in application settings or diagnostics.
- Preserve drag, click-to-toggle, persistent login, compact styling, browser/reload actions, and existing Exit semantics throughout the migration.
- Character packs are data and assets only. No DLL, arbitrary XAML, HTML, JavaScript, CSS, remote asset fetching, or command execution.
- Schemas: character/clip/persona `1`, reaction href `r1`, settings `2`. Enforce duplicate-key and unknown-property rules from the specification.
- Marker authority is animation/status only. Model output cannot trigger native commands, navigation, prompt submission, pack selection, file writes, or exit.
- RP context is visible and explicitly submitted using native ChatGPT. Never silently replace a draft or repeatedly resend context.
- Native commands are entered in PetGPT's command window. Do not claim interception inside ChatGPT's composer.
- Keep source changes small and reviewable. Update `docs/current-state.md` with actual checks after each material slice.
- Testing commands below are intended for a Windows development environment. A Linux cross-build is not evidence of working WPF/WebView2 behavior.
- Executable implementation and test code are intentionally absent from this planning deliverable, as requested. Each task specifies concrete behavior, inputs, expected outcomes, and validation commands.

## Execution and review discipline

Each task should end in a small commit with its tests and current-state update. A task is not complete because files exist: verify the stated outcome. Recheck source drift before later sessions; read the handoff, the current-state document, shared contracts, and the current task before pulling unrelated files into context.

The plan intentionally avoids changing project instructions, sending user messages, committing remotely, or implementing the refactor during this architecture request. Future implementation authorization should name a starting task or phase; T0/T1 evidence must precede enabling the web-dependent behavior.
